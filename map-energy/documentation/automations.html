Automations

Automations let MAP Energy respond to schedules, battery levels, EV charging, smart tariff events and energy conditions automatically — or pass those events into Home Assistant to extend your automations across your home.

What are MAP Energy automations?

MAP Energy automations allow you to create rules that monitor your energy system and perform an action when a particular event or condition occurs.

An automation is built around a simple idea: when something happens, MAP Energy performs the action you have configured.

Automations run in the background

Once an automation has been created and enabled, MAP Energy monitors it through the MAP Energy service. You do not need to keep the mobile app open for an automation to run.

Conditions and time windows

A trigger tells MAP Energy when something has happened. Conditions can provide an additional check before the configured action is allowed to run.

Depending on the automation type, you can restrict when an automation is allowed to operate or prevent an action when another energy condition is not suitable.

Example
When EV charging starts
Check Battery and configured blocking conditions
Then Adjust the Powerwall backup reserve

Time windows can also be used where available so that an event-triggered automation only acts during the period that is relevant to you.

Home Assistant webhooks

If you have connected Home Assistant to MAP Energy, a Home Assistant Webhook can be selected as an automation action.

Instead of changing a Powerwall setting directly, MAP Energy sends information about the event to your Home Assistant webhook. Home Assistant can then use that information as the starting point for its own automation.

⌂
MAP Energy → Home Assistant

This allows a MAP Energy event to extend beyond your Powerwall. For example, Home Assistant could respond by controlling another compatible device, running a scene, sending its own notification or starting another Home Assistant automation.

Example
When EDF Smart Bolt-On smart charging starts
Then Send a Home Assistant webhook event
HA Home Assistant receives map_energy_smart_charging_started

Understanding the webhook payload

The payload is designed to give Home Assistant enough context to decide what should happen next.

event

A machine-readable MAP Energy event name that can be used to identify what happened.

message

A human-readable description of the event.

automation

Information about the MAP Energy automation that generated the webhook.

trigger

Describes the trigger type and, where applicable, the specific event that caused the automation to run.

occurred_at

The timestamp showing when the MAP Energy event occurred.

data

Additional event-specific information can be provided here when required.

Mappy tip

The event name is particularly useful when building Home Assistant automations. It gives you a predictable value that can be checked before deciding which Home Assistant action should run.

Backup reserve automations

Backup reserve is one of the most useful Powerwall controls available to MAP Energy automations.

It can be used to preserve stored energy, encourage charging or return your Powerwall to your normal reserve after another automation has completed.

Tesla does not support backup reserve values between 81% and 99%. MAP Energy has been designed with this restriction in mind and will not intentionally submit an unsupported reserve value to Tesla.

MAP Energy handles unsupported reserve values

Where an automation captures your current reserve for later restoration, MAP Energy allows you to choose whether 80% or 100% should be used if the captured value falls within Tesla's unsupported 81–99% range.

Using multiple actions

Some energy strategies require more than one action to take place together.

MAP Energy supports grouped automation behaviour where compatible actions can be coordinated as part of the same automation event.

This can include Powerwall controls as well as connected actions such as sending the event to Home Assistant.

Example
When Smart charging starts
Then Apply the configured Powerwall behaviour and send the event to Home Assistant

Automation history

MAP Energy records automation activity so that you can see what happened after an automation was due to run.

Automation history can show successful actions as well as blocked or failed runs, helping you understand why a particular action did or did not take place.

Mappy tip

If an automation does not appear to have worked, check its history first. MAP Energy records the result of the run and, where available, the reason an action was blocked or failed.

What happens if an action fails?

MAP Energy relies on connected services such as Tesla, supported EV or energy providers and user-configured integrations to carry out some automation actions.

Temporary service availability, API errors or communication problems can occasionally prevent an action from completing. MAP Energy includes execution and retry handling for supported actions, and the result is recorded in your automation history.

A successful history entry is intended to represent a successfully completed action rather than simply the automation having reached its scheduled time.

Does the MAP Energy app need to stay open?

No. MAP Energy automations are processed by the MAP Energy service, so closing the app or locking your phone does not stop your enabled automations from running.

Need help?

If an automation is not behaving as expected, start by checking its configuration and automation history in MAP Energy.

The history can help identify whether the automation triggered, whether a condition prevented it from running, or whether a connected service returned an error.

You can also contact MAP Energy support if you need help diagnosing an automation or connected service.
